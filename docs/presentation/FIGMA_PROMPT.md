## A) ข้อกำหนดร่วม (วางก่อนเสมอ)

```
ออกแบบสื่อประชาสัมพันธ์โปรเจกต์จบการศึกษา "SmartMart POS" — ระบบขายหน้าร้าน (POS) บนเว็บสำหรับร้านสะดวกซื้อ
ผู้ชม: กรรมการ/อาจารย์ และเจ้าของร้านขนาดเล็ก ภาษาหลัก: ไทย (ชื่อระบบและคำเทคนิคเป็นอังกฤษได้)
โทน: ทันสมัย สะอาด น่าเชื่อถือ ไม่หวือหวา ใช้พื้นที่ว่างเยอะ ไม่มีภาพสต็อกแนว AI/คนยิ้มทั่วไป

อัตลักษณ์ภาพ (ต้องตรงกับหน้าเว็บจริง):
- สี: Navy #0B1F4B (พื้นเข้ม/หัวข้อ), Blue #2563FF (ปุ่ม/จุดเน้น), Lavender #C9C2F5 และ #E9E6FF (พื้นการ์ด/ไอคอน), พื้นหลัง #F7F8FC, ตัวอักษรเนื้อหา #33405F, ขาว #FFFFFF
- สีสถานะ (ใช้เฉพาะความหมายสถานะ): เขียว #0E7A4F, ส้ม #B45309, แดง #B42318
- ฟอนต์: Prompt (หัวข้อ ตัวเลขเด่น ปุ่ม; น้ำหนัก 600–700) + Noto Sans Thai (เนื้อหา; 400–500) — ไม่ใช้ letter-spacing ติดลบกับภาษาไทย
- องค์ประกอบ: การ์ดขาวกรอบบาง #DCE3F7 มุมโค้ง 12–24px, พื้นเข้มไล่เฉด Navy→Blue เป็นแถบ/ปก, หัวข้อมีเส้นใต้สีน้ำเงินสั้น (กว้าง 44 สูง 4), ไอคอนเส้นบาง stroke 1.8
- โลโก้: วงกลมสีน้ำเงินมีเครื่องหมายถูก + คำว่า SMARTMART (ตัวอักษรละติน เว้นระยะ) ถ้าไม่มีไฟล์ให้วาดแบบเรียบง่ายตามนี้

กฎเนื้อหา:
- ใช้ข้อความตามที่ให้เท่านั้น ห้ามแต่งตัวเลข/ฟีเจอร์เพิ่ม ห้ามอ้างว่า "ใช้งานจริงแล้ว" หรือ "รับเงินจริง"
- ต้องมีบรรทัดข้อจำกัดบนสื่อ: "PromptPay เป็นโหมดทดลอง (Sandbox) · Smart BI เป็นกฎ/สถิติ ไม่ใช่ AI"
- ภาพหน้าจอระบบ: ให้ใส่เป็นกรอบ placeholder ขนาดจริงของอุปกรณ์ (เบราว์เซอร์/แท็บเล็ต) ติดป้ายชื่อหน้า (Dashboard, POS, สต็อก, รายการที่ควรสั่งซื้อ) เพื่อให้ฉันวางภาพจริงทับ ห้ามวาดข้อมูลปลอมที่ดูเหมือนข้อมูลลูกค้าจริง
- ตัวอักษรเนื้อหาไม่เล็กกว่า 9pt บนกระดาษ (โปสเตอร์ตามสัดส่วน) คอนทราสต์ตัวอักษร/พื้นอย่างน้อย 4.5:1; อย่าวางตัวอักษรสีน้ำเงิน #2563FF บนพื้น Lavender (คอนทราสต์ไม่พอ ใช้ Navy แทน)
- เว้นขอบปลอดภัย (safe margin) 8 mm และ bleed 3 mm สำหรับพิมพ์
- จัดชั้นใน Figma ให้เป็นระเบียบ: ตั้งชื่อเลเยอร์ ใช้ Auto Layout ใช้ Variables/Styles สำหรับสีและฟอนต์ เพื่อแก้ทีเดียวทั้งไฟล์
- ผลงาน: แยก Page "Brochure" และ "Poster" ในไฟล์เดียวกัน
```

## B) โบรชัวร์

```
สร้างโบรชัวร์ A4 แนวนอน พับ 3 (tri-fold) 2 หน้า (ด้านนอก/ด้านใน) แต่ละพับกว้าง 99 mm สูง 210 mm
(ถ้าพับ 3 แบบ Z หรือแบบพับเข้า ให้ทำแบบพับเข้า (letter fold) และทำให้พับที่พับเข้าแคบกว่าอีก 1–2 mm)

หน้านอก (ด้านที่เห็นตอนปิด):
- พับขวา = ปก: โลโก้ + ชื่อ "SmartMart POS" + สโลแกน "ขายง่าย สต็อกแม่น ร้านเดินหน้า" + กรอบภาพ Dashboard บนพื้น Navy ไล่เฉดไป Blue
- พับกลาง = ปกหลังด้านใน: หัวข้อ "ตัวเลขที่ตรวจสอบได้" การ์ด 3 ใบ: "196 เคส — ทดสอบอัตโนมัติผ่านทั้งหมด", "170 ข้อ — ทดสอบสิทธิ์ผ่าน HTTP จริง ผ่านทั้งหมด", "3 ขนาดจอ — คอมพิวเตอร์ แท็บเล็ต มือถือ (ตรวจในเบราว์เซอร์; ยังไม่ทดสอบบน iPhone/iPad จริง)"
- พับซ้าย = ติดต่อ: ชื่อผู้พัฒนา [ชื่อ-นามสกุล], สถาบัน [ชื่อสถาบัน/คณะ], อาจารย์ที่ปรึกษา [ชื่อ], ช่องทางติดต่อ [อีเมล/โทร], QR code ไปที่ https://smartmart-pos-sage.vercel.app/ พร้อมข้อความ "ลองใช้งานระบบตัวอย่าง"

หน้าใน (เปิดออก 3 พับต่อเนื่อง):
- พับ 1 "ปัญหา → ระบบช่วย": 7 แถวคู่
  1) สินค้าหมดอายุคาชั้น → สต็อกแยกเป็นล็อต ตัดของใกล้หมดอายุก่อน (FEFO) และแจ้งเตือน
  2) ไม่รู้ควรสั่งอะไรเพิ่ม → รายการที่ควรสั่งซื้อ บอกจำนวนแนะนำและมูลค่า ส่งออกไฟล์ได้
  3) ลูกค้าประจำไม่ผูกพัน → สมาชิกสะสมแต้มตามยอดซื้อ
  4) ราคา/ส่วนลดคิดผิด → ระบบคำนวณจากฐานข้อมูลฝั่งเซิร์ฟเวอร์เสมอ
  5) เงินสดไม่ตรง → ปิดกะ/นับเงินสด เทียบยอดที่ควรมีและบันทึกส่วนต่าง
  6) ลูกค้าคืนของ/ยกเลิกบิล → คืนเข้าล็อตเดิม กลับรายการแต้ม บันทึกเหตุผลและผู้ทำรายการ
  7) ไม่รู้ใครทำอะไร → Audit log ทุกการกระทำสำคัญ
- พับ 2 "ฟีเจอร์หลัก": 4 การ์ดไอคอน — ขายหน้าร้าน (เงินสด + PromptPay QR, พิมพ์ใบเสร็จ 80 มม.), สต็อกและการสั่งซื้อ, สมาชิกและโปรโมชั่น, แดชบอร์ดและรายงาน (Smart BI, ส่งออก CSV, เรียงตารางได้) พร้อมกรอบภาพ POS และ Dashboard
- พับ 3 "สิทธิ์ผู้ใช้ 3 ระดับ + ความปลอดภัย": ตาราง 3 คอลัมน์ แคชเชียร์ / เจ้าของร้าน / ผู้ดูแลระบบ พร้อมสิ่งที่ทำได้โดยย่อ (แคชเชียร์: ขาย ดูคลัง ปิดกะ · เจ้าของร้าน: + ยกเลิกบิล จัดการสินค้า สมาชิก โปรโมชั่น ดูรายงาน · ผู้ดูแลระบบ: ทุกอย่าง รวมผู้ใช้ ตั้งค่า Audit) และบรรทัดความปลอดภัย "ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ · จำกัดล็อกอินผิดซ้ำ · สถานะ 'ชำระแล้ว' ตั้งได้หลังผู้ให้บริการชำระเงินยืนยันเท่านั้น"
- ท้ายหน้าใน: บรรทัดเทคโนโลยีตัวเล็ก "Next.js · TypeScript · PostgreSQL · Prisma · Tailwind" และบรรทัดข้อจำกัดตามกฎร่วม
```

## C) โปสเตอร์

```
สร้างโปสเตอร์ A2 แนวตั้ง (420 x 594 mm) สำหรับนำเสนอโปรเจกต์ ดูจากระยะ 1–2 เมตรต้องอ่านหัวข้อออก
ลำดับสายตา: หัวข้อใหญ่ → ภาพระบบ → 4 จุดเด่น → ตัวเลขทดสอบ → ติดต่อ/QR

โครงจากบนลงล่าง:
1) แถบหัว (พื้น Navy ไล่เฉดไป Blue, สูง ~22%): โลโก้ + "SmartMart POS" (Prompt 700 ขนาดใหญ่มาก) + สโลแกน "ขายง่าย สต็อกแม่น ร้านเดินหน้า" + บรรทัดรอง "ระบบขายหน้าร้านบนเว็บสำหรับร้านสะดวกซื้อ · โปรเจกต์จบการศึกษา"
2) ภาพหลัก (~25%): กรอบเบราว์เซอร์ placeholder ใหญ่ "Dashboard" ซ้อนกรอบแท็บเล็ต "POS" เหลื่อมกันเล็กน้อย พร้อมเงาบาง
3) 4 จุดเด่น (การ์ด 2x2, ~20%): ไอคอนใหญ่ + หัวข้อ + 1 บรรทัด
   - ขายได้ทั้งเงินสดและ PromptPay QR — ยืนยันการจ่ายจากผู้ให้บริการเท่านั้น
   - สต็อกแยกล็อต ตัดของใกล้หมดอายุก่อน (FEFO)
   - สมาชิกสะสมแต้ม และโปรโมชั่นคำนวณฝั่งเซิร์ฟเวอร์
   - แดชบอร์ด รายงาน และรายการที่ควรสั่งซื้อ (ส่งออก CSV)
4) แถบตัวเลข (~10%, พื้น Lavender #E9E6FF ตัวอักษร Navy): "196 เคส ทดสอบอัตโนมัติ" · "170 ข้อ ทดสอบสิทธิ์ผ่าน HTTP" · "3 บทบาท แคชเชียร์ / เจ้าของร้าน / ผู้ดูแลระบบ" (ตัวเลขใหญ่ Prompt 700)
5) แถบสถาปัตยกรรมย่อ (~8%): แผนภาพกล่อง 4 ชั้นเรียบ ๆ "เบราว์เซอร์ → Next.js (Server Actions + ตรวจสิทธิ์) → ชั้น Service (ธุรกิจ) → PostgreSQL" และไอคอน Provider ชำระเงินเชื่อมที่ชั้น Service
6) แถบท้าย (~15%, พื้น Navy): ซ้าย ชื่อผู้พัฒนา [ชื่อ-นามสกุล] สถาบัน [ชื่อสถาบัน/คณะ] อาจารย์ที่ปรึกษา [ชื่อ] ช่องทางติดต่อ [อีเมล/โทร]; ขวา QR code ใหญ่ไปที่ https://smartmart-pos-sage.vercel.app/ พร้อมข้อความ "สแกนเพื่อลองระบบตัวอย่าง"; ล่างสุดตัวเล็ก: "PromptPay เป็นโหมดทดลอง (Sandbox) · Smart BI เป็นกฎ/สถิติ ไม่ใช่ AI"

ข้อจำกัดเลย์เอาต์: ข้อความในโปสเตอร์ไม่เกินที่ระบุ ห้ามเพิ่มย่อหน้ายาว; หัวข้อหลักไม่เล็กกว่า 120 pt, หัวข้อการ์ด 48 pt, เนื้อความ 24 pt ขึ้นไป
```
