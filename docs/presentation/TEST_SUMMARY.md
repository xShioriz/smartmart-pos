## 2) ทดสอบสิทธิ์ผ่าน HTTP จริง — `scripts/test-auth-guards.mjs`
ยิงคำขอจริงเข้าเซิร์ฟเวอร์ ตรวจว่า
- ไม่ล็อกอิน → ถูกส่งไป `/login` / API ตอบ 401
- แคชเชียร์เข้าหน้า/endpoint ของแอดมิน (สินค้า รายงาน ผู้ใช้ ตั้งค่า audit ประวัติกะ ส่งออก CSV) ไม่ได้ → 403
- ส่งออก CSV: ตรวจพารามิเตอร์ผิด/ช่วงเกิน 366 วัน → 400
- เปิด/ปิดกะครบทั้งขั้นตอน แล้วล้างข้อมูลทดสอบ

ผลล่าสุด: **ALL PASS 170 ข้อ** (รันกับ production build บนเครื่อง 2026-11-10 หลังเพิ่มฟีเจอร์ v1.5) เพิ่มใหม่: CSV รายการสั่งซื้อ (ไม่ล็อกอิน → /login, CASHIER → 403, ADMIN → 200 + BOM), หน้า `/inventory/reorder` ตามสิทธิ์, หน้าที่เรียงได้และช่วงวันที่ Dashboard ตอบ 200 แม้พารามิเตอร์แปลก

## 4) ทดสอบด้วยมือบน Production (Vercel + Neon แยกฐานจาก dev)
ผู้พัฒนาทดสอบเองและผ่านทั้งหมด:
- ล็อกอิน admin / cashier; cashier เข้าหน้าแอดมินไม่ได้
- ขายเงินสด → ใบเสร็จ → สต็อกลดถูกต้อง
- ขาย PromptPay QR (Sandbox) → กด Mark as paid ที่ Omise → บิลเปลี่ยนเป็นชำระแล้ว
- คืนสินค้า, ดู Dashboard / รายงาน / ตั้งค่า
- เปิด/ปิดกะ, ส่งออก CSV, ล็อกอินผิดเกินเกณฑ์ถูกล็อกชั่วคราว
- ระบบเรียงลำดับตาราง (v1.4) และธีมใหม่ (v1.5): หลัง merge v1.5 ผู้พัฒนาตรวจบน production ด้วยมือ (เรียงตาราง, ขายเงินสด, Dashboard) **ผ่านทั้งหมด** — ผลตามที่ผู้พัฒนาแจ้ง ไม่ได้ตรวจซ้ำโดยสคริปต์

## 5) สิ่งที่ยังไม่ได้ทดสอบ / ข้อจำกัด (ควรตอบกรรมการตรงไปตรงมา)
- **อุปกรณ์จริง**: Responsive ตรวจในเบราว์เซอร์ที่ 375 / 768 / 1024 px เท่านั้น ยังไม่ได้ลองบน iPhone / iPad จริง (แป้นตัวเลข แถบตะกร้า)
- **ทดสอบโหลด**: ไม่ได้ทดสอบผู้ใช้พร้อมกันจำนวนมาก; การนับล็อกอินผิดไม่ atomic เต็มรูปแบบ
- **PromptPay**: ใช้ Sandbox เท่านั้น ไม่เคยรับเงินจริง; คืนเงินบิล QR ต้องโอนนอกระบบ
- **ไม่มีการกันสต็อกระหว่างรอสแกน QR** (ตรวจสต็อกซ้ำตอนยืนยันการจ่าย)
- **การเรียงภาษาไทย** ใช้ ICU ของ Node ในแอป (ตรวจกับข้อมูล 44 สินค้า) ไม่ได้ทดสอบกับข้อมูลหลักหมื่นรายการ
- ไม่มี end-to-end test อัตโนมัติผ่านเบราว์เซอร์ (หน้าจอทดสอบด้วยมือ)
