# SmartMart POS — สรุปข้อมูลสำหรับทำสื่อ (โบรชัวร์ / โปสเตอร์ / สไลด์)

ข้อมูลทุกข้อมาจากระบบจริง ณ เวอร์ชัน v1.6 (2026-11-14) ส่วน "ข้อจำกัด" ควรพูดตรง ๆ กับผู้ชม อย่าตัดออกจากสื่อ

## 1) ภาพรวม
- **ชื่อ**: SmartMart POS
- **คืออะไร**: ระบบขายหน้าร้าน (POS) สำหรับร้านสะดวกซื้อ ทำงานบนเว็บ ใช้ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ
- **ประเภทงาน**: โปรเจกต์จบการศึกษา (พัฒนาโดยผู้พัฒนาคนเดียว)
- **เว็บตัวอย่าง**: https://smartmart-pos-sage.vercel.app/
- **จุดขาย 1 บรรทัด**: ขายเร็ว สต็อกแม่นถึงระดับล็อต เห็นตัวเลขร้านชัดในหน้าเดียว และตรวจสอบย้อนหลังได้ทุกรายการ
- **ตัวเลือกสโลแกน** (เลือกหรือปรับได้): "ขายง่าย สต็อกแม่น ร้านเดินหน้า" · "POS ที่ร้านสะดวกซื้อใช้ได้ตั้งแต่วันแรก" · "จากหน้าร้านถึงตัวเลข ในระบบเดียว"

## 2) ปัญหาที่แก้ → สิ่งที่ระบบทำ
| ปัญหาของร้าน | ระบบช่วยอย่างไร |
|---|---|
| สินค้าหมดอายุคาชั้น | สต็อกแยกเป็นล็อตมีวันหมดอายุ ตัดล็อตที่หมดอายุก่อนอัตโนมัติ (FEFO) และแจ้งเตือนล่วงหน้า |
| ไม่รู้ว่าควรสั่งอะไรเพิ่ม | หน้า "รายการที่ควรสั่งซื้อ" บอกจำนวนแนะนำและมูลค่าโดยประมาณ ส่งออกเป็นไฟล์ได้ |
| ลูกค้าประจำไม่ผูกพัน | สมาชิกสะสมแต้มตามยอดซื้อ |
| ราคา/ส่วนลดคิดผิด | ระบบคำนวณราคาและโปรโมชั่นฝั่งเซิร์ฟเวอร์จากฐานข้อมูลเสมอ |
| เงินสดในลิ้นชักไม่ตรง | ปิดกะ/นับเงินสด เทียบกับยอดที่ควรมี และบันทึกส่วนต่างพร้อมหมายเหตุ |
| ลูกค้าคืนของ / ยกเลิกบิล | คืนสินค้าเข้าล็อตเดิม กลับรายการแต้ม บันทึกเหตุผลและผู้ทำรายการ |
| ไม่รู้ใครทำอะไร | Audit log ทุกการกระทำสำคัญ |

## 3) ฟีเจอร์หลัก (จัดกลุ่มสำหรับทำโบรชัวร์)
**ขายหน้าร้าน (POS)**
- ขายเงินสด คำนวณเงินทอน พิมพ์ใบเสร็จ (รองรับกระดาษ 80 มม.)
- ขายด้วย PromptPay QR — ระบบถือว่า "จ่ายแล้ว" ก็ต่อเมื่อผู้ให้บริการชำระเงินยืนยันเท่านั้น ไม่เชื่อการกดของพนักงาน
- ค้นหา/สแกนสินค้า เลือกสมาชิกตอนขาย ใช้โปรโมชั่นอัตโนมัติ
- กันบิลซ้ำเมื่อกดซ้ำหรืออินเทอร์เน็ตสะดุด

**สต็อกและการสั่งซื้อ**
- รับสินค้าเข้าเป็นล็อต (ทุน วันหมดอายุ เลขล็อต) ปรับสต็อกพร้อมเหตุผล
- ตัดสต็อกแบบ FEFO สต็อกไม่ติดลบ
- แจ้งเตือนสินค้าใกล้หมด/ใกล้หมดอายุ
- รายการที่ควรสั่งซื้อ + ส่งออก CSV

**สมาชิกและโปรโมชั่น**
- สมาชิก: รหัส เบอร์โทร ประวัติการซื้อ แต้มสะสม
- โปรโมชั่น: ลดรายการ / ลดทั้งบิล กำหนดช่วงเวลา

**ตัวเลขและรายงาน (Smart BI)**
- Dashboard: ยอดขาย จำนวนบิล แนวโน้ม เลือกช่วงวันที่เองได้
- รายงานยอดขายรายวัน สินค้าขายดี ส่งออก CSV เปิดใน Excel ภาษาไทยได้
- Smart BI แบบกฎ/สถิติ (ไม่ใช้ AI): แนวโน้ม สินค้าควรสั่งเพิ่ม สินค้าขายช้า สินค้าใกล้หมดอายุ และแสดงวิธีคำนวณทุกข้อ
- กดหัวตารางเพื่อเรียงลำดับ (ตัวอักษรไทย จำนวน สถานะ วันหมดอายุ)

**การควบคุมและความปลอดภัย**
- 3 บทบาทผู้ใช้ (ดูหัวข้อ 4)
- Audit log, ตั้งค่าร้าน
- จำกัดการล็อกอินผิดซ้ำ: ผิด 5 ครั้งใน 15 นาที ล็อกชั่วคราว
- ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกครั้ง ไม่พึ่งการซ่อนปุ่ม
- ส่งออก CSV กัน formula injection

## 4) บทบาทผู้ใช้
| บทบาท | ทำอะไรได้ |
|---|---|
| **แคชเชียร์** | ขาย (POS), ดูคลังแบบดูอย่างเดียว, ดูบิลของตนเอง, เปิด/ปิดกะของตนเอง |
| **เจ้าของร้าน** (ใหม่ v1.6) | ทุกอย่างของแคชเชียร์ + ดูบิลทุกคน + คืนสินค้า/ยกเลิกบิล + จัดการสินค้า หมวดหมู่ โปรโมชั่น สมาชิก + ดู Dashboard/รายงาน/รายการสั่งซื้อ |
| **ผู้ดูแลระบบ** | ทุกอย่าง รวมผู้ใช้งาน ตั้งค่า Audit Log การแจ้งเตือน รับ/ปรับสต็อก และตรวจสอบบิล "จ่ายแล้วแต่ต้องตรวจสอบ" |

## 5) เทคโนโลยี (สำหรับส่วนท้ายสไลด์)
Next.js 16 · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui · Recharts · Prisma 6 · PostgreSQL (Neon) · Zod · Opn Payments (Omise) สำหรับ PromptPay · โฮสต์บน Vercel

## 6) หลักการออกแบบระบบ (พูดกับกรรมการได้)
- logic ธุรกิจอยู่ชั้น service เดียว ทุก action ตรวจ Zod → ตรวจสิทธิ์ → เรียก service
- เงินคำนวณด้วย Decimal ไม่ใช้ตัวเลขทศนิยมปกติ; เวลาใช้เขตเวลาไทย
- ไม่เชื่อราคา/ยอดรวม/ส่วนลด/สต็อกจากเบราว์เซอร์
- สถานะ "ชำระแล้ว" ตั้งได้ทางเดียว: หลังผู้ให้บริการยืนยัน

## 7) ตัวเลขที่อ้างได้ (จากการรันจริง)
- ทดสอบอัตโนมัติ **196 เคส** ผ่านทั้งหมด (16 ชุด)
- ทดสอบสิทธิ์ผ่าน HTTP จริง **170 ข้อ** ผ่านทั้งหมด (ผลรันบนเครื่อง 2026-11-14)
- ตรวจ 16 หน้า × 3 ขนาดจอ (375 / 768 / 1440 px) ไม่ล้นจอ
- ผู้พัฒนาทดสอบมือบนเว็บจริง: ล็อกอิน ขายเงินสด ใบเสร็จ สต็อก QR (Sandbox) คืนสินค้า เปิด/ปิดกะ ส่งออก CSV เรียงตาราง Dashboard — ผ่าน
- ข้อมูลสาธิต: บิลเงินสดย้อนหลัง 30 วัน (ใช้ตอนนำเสนอ)

- ลักษณะ: การ์ดขาวกรอบบาง มุมโค้ง แถบข้างสี Navy ไล่เฉด หัวข้อมีเส้นใต้สีน้ำเงินสั้น ๆ
- โลโก้: ไอคอนเครื่องหมายถูกในวงกลม + คำว่า SMARTMART (ไฟล์ SVG อยู่ที่ `src/components/layout/brand-logo.tsx`)

## 10) ข้อจำกัด (ควรบอกผู้ชม)
- PromptPay เป็น **Sandbox** — ยังไม่เคยรับเงินจริง การรับเงินจริงต้องมีบัญชีผู้ขายกับผู้ให้บริการ
- คืนเงินบิล QR ต้องโอนคืนนอกระบบ (ระบบบันทึกหมายเหตุไว้)
- ไม่กันสต็อกระหว่างรอลูกค้าสแกน QR (ตรวจซ้ำตอนยืนยัน)
- ยังไม่มีแลกแต้มเป็นส่วนลด (มีเฉพาะสะสม)
- ยังไม่ได้ทดสอบบน iPhone/iPad จริง, ไม่ได้ทดสอบโหลดผู้ใช้พร้อมกันจำนวนมาก, ไม่มี end-to-end test อัตโนมัติผ่านเบราว์เซอร์
- Smart BI เป็นกฎ/สถิติ ไม่ใช่ AI ทำนาย

## 11) ข้อความสำเร็จรูป
**พิทช์ 30 วินาที**
"SmartMart POS คือระบบขายหน้าร้านบนเว็บสำหรับร้านสะดวกซื้อ ขายได้ทั้งเงินสดและ PromptPay QR สต็อกแยกเป็นล็อตและตัดของที่ใกล้หมดอายุก่อน เจ้าของร้านเห็นยอดขาย สินค้าที่ควรสั่งเพิ่ม และตรวจสอบย้อนหลังได้ทุกรายการ แบ่งสิทธิ์แคชเชียร์ เจ้าของร้าน และผู้ดูแลระบบ ผ่านการทดสอบอัตโนมัติ 196 เคส"

**พาดหัวโปสเตอร์ (ตัวอย่าง)**
- หัวข้อ: **SmartMart POS — ขายง่าย สต็อกแม่น ร้านเดินหน้า**
- 4 ไอคอนเด่น: ขายเงินสด/QR · สต็อกล็อต FEFO · สมาชิกและแต้ม · แดชบอร์ดและรายงาน
- แถบล่าง: เว็บตัวอย่าง + QR code ไปที่ https://smartmart-pos-sage.vercel.app/ + ชื่อผู้พัฒนา/สถาบัน

**โครงโบรชัวร์ 3 พับ**
1. หน้าปก: ชื่อ สโลแกน ภาพ Dashboard
2. ด้านใน: "ปัญหา → ระบบช่วย" (ตารางหัวข้อ 2) + ฟีเจอร์หลัก 4 กลุ่ม
3. ด้านใน: บทบาทผู้ใช้ + ความปลอดภัย
4. ปกหลัง: ตัวเลขทดสอบ + เทคโนโลยี + ข้อจำกัดโดยย่อ + ช่องทางติดต่อ

## 12) สิ่งที่ผู้ทำสื่อต้องเติมเอง
ชื่อผู้พัฒนา สถาบัน/อาจารย์ที่ปรึกษา ช่องทางติดต่อ โลโก้สถาบัน และภาพหน้าจอจริง (เอกสารนี้ไม่ใส่ข้อมูลส่วนตัวหรืออีเมล/รหัสผ่านใด ๆ)
